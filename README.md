# 🧠 Brain (`.brn`)

A strictly typed, deterministic transpiler written in Rust that compiles Brain (`.brn`) skill files into standard, clean Markdown skills for **OpenCode** and **Claude**.

> **Disclaimer: Work in Progress / Proof of Concept**
>
> Brain is currently an experimental **proof-of-concept (PoC)** under active development. The language syntax, attribute names, and compiler output are subject to change. It is not yet feature-complete or intended for mission-critical production environments without review. Feedback, experiments, and contributions are welcome!

## Features

- **Brain Skill Syntax**: Write skills with object-oriented constructs, attributes, typed parameters, `if/else`, `while`, and `try/catch` fallback blocks.
- **Strictly Typed & Deterministic**: Zero randomness or LLM hallucination in generation. Bit-for-bit identical markdown output every compile.
- **Dual Platform Targets**: Compiles to OpenCode (`.opencode/skills/<skill>/SKILL.md`) and Claude (`.claude/skills/<skill>/SKILL.md`).
- **Watermark & Overwrite Safety**: Protects hand-written skills from accidental destruction. Only skills generated by `brain` are modified unless `--force` is specified.
- **Smart Init**: Automatically detects `.opencode` or `.claude` directories in your project, or prompts you interactively.
- **Watch Mode**: Live compiler watches `.brains/` and recompiles skills on save.

## Quickstart

### 1. Initialize in your project
```bash
brain init
```
This detects existing `.opencode` or `.claude` directories, creates `.brains/brain.toml`, and generates a starter file `.brains/Starter.brn`.

### 2. Scaffold a New Skill
```bash
brain new code-review
```
This generates `.brains/code-review/CodeReviewSkill.brn`.

You can also place supporting assets (scripts, JSON schemas, reference docs) right inside `.brains/code-review/`. On build, `brain` compiles the `.brn` file into `SKILL.md` and copies all supporting files into the target skill directory.

### 3. Write a Skill (`.brains/code-review/CodeReviewSkill.brn`)
```brain
[Skill("git-commit", "Generates conventional commit messages by analyzing changes.")]
[Trigger("commit", "write commit")]
[Requires("git")]
[Guardrail("Never commit directly without explicit confirmation")]
[Rule("Keep subject line under 50 characters")]
[Precondition("Git repo exists and has changes")]
[Example(Input = "Fix typo in README", Output = "docs: fix typo in README")]
public class GitCommitSkill
{
    public void Run(string scope = "", bool terse = false)
    {
        if (terse)
        {
            Prompt("Draft single concise line under 50 characters.");
        }
        else
        {
            Prompt($"Draft conventional commit: type({scope}): concise summary.");
        }

        try
        {
            AnalyzeChanges();
        }
        catch (DiffTooLargeException)
        {
            Prompt("Diff exceeds context limit. Fall back to file summary.");
        }
    }

    private void AnalyzeChanges()
    {
        Execute("git diff --staged");
        Prompt("Inspect staged git changes and determine component impact.");
    }
}
```

### 4. Compile Skills
```bash
brain build
```

Or target only OpenCode or Claude:
```bash
brain build --target opencode
brain build --target claude
```

Force overwrite foreign skills:
```bash
brain build --force
```

### 5. Modular Skills with `using` Imports

You can organize large skills across multiple files or share reusable routines across skills:

#### Rule: Skills vs Library Modules
- **Standalone Skill (`[Skill(...)]`)**: Emits a `SKILL.md` under `.opencode/skills/<name>/` and `.claude/skills/<name>/`.
- **Reusable Library Module (no `[Skill]`)**: Any `.brn` file without `[Skill]` is treated as an imported module. Its rules, guardrails, and procedures are cleanly composed into importing skills, and it is **never** emitted as an orphaned, empty skill.

#### A. Importing a Sibling File in the Same Skill Folder
```brain
// In .brains/code-review/DiffHelpers.brn (No [Skill] attribute)
public class DiffHelpers
{
    public void ScanStagedFiles(int maxFiles)
    {
        while ($"There are uninspected diffs (processed < {maxFiles})")
        {
            Prompt("Analyze next diff chunk.");
        }
    }
}
```

```brain
// In .brains/code-review/CodeReviewSkill.brn
using "./DiffHelpers.brn";

[Skill("code-review", "Reviews PR code changes")]
public class CodeReviewSkill
{
    public void Run(int maxFiles = 10)
    {
        // Directly invoke procedure imported from sibling file:
        ScanStagedFiles(maxFiles);
    }
}
```

#### B. Importing from a Shared Module
```brain
// In .brains/shared/CommonRules.brn (No [Skill] attribute)
[Rule("Always run tests before completing PR")]
[Never("commit secrets or .env files")]
public class CommonRules
{
    public void VerifyGitClean()
    {
        Execute("git status");
    }
}
```

```brain
// In .brains/code-review/CodeReviewSkill.brn
using "../shared/CommonRules.brn";

[Skill("code-review", "Reviews PR code changes")]
public class CodeReviewSkill
{
    public void Run()
    {
        VerifyGitClean();
    }
}
```

Path resolution supports both relative paths (`using "./file.brn";`, `using "../shared/rules.brn";`) and dot module syntax (`using Shared.CommonRules;`).

## Editor Setup & Syntax Highlighting

### Zed
1. In Zed, press `Ctrl+Shift+P` (or `Cmd+Shift+P`).
2. Search and run: **`zed: install dev extension`**.
3. Select the `editors/zed` directory from this repository:
   ```text
   /path/to/sebastian/editors/zed
   ```
4. All `.brn` files will now have Tree-sitter syntax highlighting, bracket matching, and `//` comment toggling.

### VS Code & Cursor
Install the pre-packaged `.vsix` extension bundle:
```bash
# For VS Code:
code --install-extension editors/vscode/brain-lang-0.1.0.vsix

# For Cursor:
cursor --install-extension editors/vscode/brain-lang-0.1.0.vsix
```

Alternatively, you can package or update it from source:
```bash
cd editors/vscode
npx @vscode/vsce package
code --install-extension brain-lang-0.1.0.vsix --force
```
